# 配色配方預測（Color Recipe Predictor）

以 Kubelka-Munk 理論建立「配方 → 顏色」的預測模型，再反解「目標色 → 配方」，
並用歷史配方把模型校正到實際生產狀況。純網頁版，以桌機瀏覽器使用為主。

## 使用方式

不需安裝。根目錄的 `index.html` 是打包好的單一檔案，程式與字型都內嵌在裡面，
可發佈到 GitHub Pages（從 `main` 根目錄發佈），也可以下載後直接開啟。

第一次打開時按標題列的 **載入範例資料**，裡面有一組自洽的示範資料
（白 + 紅黃藍黑四支色母、六張歷史配方），可以直接試跑反解。

## 三個分頁

| 分頁 | 做什麼 |
| --- | --- |
| **配方工作台** | 輸入目標色、勾選要用的色料，反解出濃度組合；檢視可達色域、置換模擬、劑量掃描 |
| **色料資料庫** | 建立 SPD／色粉與樹酯，輸入濃度曲線（顏色 vs 濃度） |
| **歷史配方** | 輸入打過樣的配方與實測色，作為校正層的訓練資料 |

## 色彩模型

目前沒有光譜資料，所以把 Lab 轉成三通道「擬反射率」（XYZ 對 D65 白點正規化），
在這三個通道上跑 Kubelka-Munk：

```
K_mix = K_resin + Σ kContrib_i(c_i)
S_mix = S_resin + Σ sContrib_i(c_i)
R     = 1 + K/S − sqrt((K/S)² + 2K/S)
```

**白還原法**：彩色料假設只吸收不散射，白（TiO₂）則 k 與 s 都擬合。
因此每支彩色料的濃度曲線都要記錄量測當時的白階，程式才能跨白階還原。
曲線點數決定擬合形式——3 點走線性、4–6 點走冪次 `α·c^γ`、7 點以上走單調 PCHIP。

### 已知限制

- **無法處理同色異譜。** 三通道模型在 D65 下對得準的兩個配方，換光源可能差很多。
  若日後取得 400–700nm 的光譜資料，資料結構已預留 `spectrum` 欄位，核心可直接升級。
- **白用的是簡化的雙常數。** 若要完整分離每支色料的 K 與 S，需要同一支色料在
  兩個以上白階的量測值。
- **量測條件必須一致。** 板厚、SCI/SCE、射出條件不同的資料不該混在一起，
  程式會用「同基礎樹酯 + 同載體 + 同量測條件」分群，只有同群的歷史配方會進校正集。

## 濃度換算

模型真正吃的是「顏料佔最終製品的重量百分比」。兩種配方形式：

```
直接添加      c = dosage × pigmentLoading / 100
母粒 letdown  c = letdown/100 × pctInMB × pigmentLoading / 100
```

**最低含量限制看的是最終製品中的顏料濃度。** 這讓約束變成不連續的：某支色料
要嘛不用（c = 0），要用就必須 ≥ 下限，中間是禁區。反解時會先在連續區間求解，
若有解落在禁區，再對這些色料分別試「拉到下限」與「歸零」兩種分支重解，取最佳者。

## 歷史配方校正

三層，由強到弱：

1. **色力係數**：每支色料一個純量，用最小二乘從歷史配方擬合。
   處理批次色力差異、分散度這類全域偏差，外插時仍可信。
   校正後若誤差沒有改善會自動放棄（通常代表歷史資料條件不一致）。
2. **殘差場**：套完色力後剩下的 ΔLab，依與歷史配方的距離做高斯加權內插。
   只在歷史配方附近生效，離得遠權重自然衰減到 0。
3. **信心分數**：量化「這個預測有多可信」，並列出扣分原因。
   外插倍數、擬合 R²、歷史支撐、跨載體與否都會影響分數。

## 本機開發

需要 Node.js 22 以上。

```bash
npm install
npm run dev     # 開發伺服器
npm run build   # 打包並更新根目錄 index.html
npm test        # 38 項測試
```

修改程式後請執行 `npm run build` 並一併提交更新後的 `index.html`，網頁版才會是最新內容。

## 測試

測試不只檢查程式不崩潰，而是用合成資料做往返驗證：

- 以已知吸收係數造曲線 → 擬合 → 應還原出原係數，外插也要對得上理論值
- 色料曲線在白階 2% 下量測，預測換到白階 4%，ΔE₀₀ < 0.5
- 已知配方算出顏色 → 當成目標反解 → 濃度誤差 < 0.08 wt%
- `direct 1% 色母` 與 `母粒含 25% × letdown 4%` 必須算出完全相同的顏色
- 刻意注入色力偏差的歷史配方 → 校正層應還原出該偏差
